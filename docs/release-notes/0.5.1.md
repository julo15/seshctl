# Seshctl 0.5.1

## Held-key transcript scroll, actually fixed this time

0.5.0 claimed the transcript-view hang on held `Ctrl+B` (and `Ctrl+F`/`D`/`U`, `j`/`k`) was resolved. It wasn't — the May fix removed two contributing factors (per-keystroke `NSView` walk, overlapping 80 ms animations) but left the dominant one untouched: each page-jump materializes 15–30 rows in one tick, and each row synchronously re-parses its markdown through cmark-gfm with no cache. A single burst could exceed the ~33 ms macOS key-repeat interval, so events queued faster than they drained and the main thread pegged at 100% CPU.

0.5.1 throttles keyboard scroll commands to ~20 Hz so the run loop has breathing room between bursts. A brief 40 ms ease-out animation is restored on each scroll — kept strictly shorter than the throttle window so animations can't queue. `g`/`G` and `gg` are now throttled too (previously they fired a SwiftUI animation tick on every key-repeat, even though the anchor target is idempotent). Trackpad scrolling is unchanged — it never used this path.

The fix is a backpressure bound, not a per-row speedup; transcripts with very heavy markdown will still feel each scroll. A future release will cache parsed markdown per turn so the underlying cost goes away.
