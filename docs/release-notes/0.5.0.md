# Seshctl 0.5.0

## Native semantic search — no Python required

Seshctl's search box now runs entirely in-app. The standalone `recall` Python CLI is gone — embedding inference, vector storage, and top-K ranking are all native Swift, backed by a quantized CoreML model that ships inside the app bundle. No `pip install`, no `~/.local/share/recall/venv/`, no first-search HuggingFace download.

The user experience is unchanged: type in the search box, results appear. On a fresh install the first query indexes your existing Claude Code, Codex, and Gemini transcripts in the background (progress shown in the search section). Subsequent searches are instant.

**Migration for 0.4.x users:** the old Python `recall` install at `~/.local/share/recall/venv/` is no longer used and can be removed at your leisure — Seshctl never touches it. To clean up, run `~/Documents/me/recall/uninstall.sh` (or wherever you originally installed recall from) and `trash ~/.local/share/recall ~/.local/bin/recall ~/.recall`. The new native index lives at `~/Library/Application Support/Seshctl/seshctl.sqlite` and builds from scratch on first search after the upgrade.

**Privacy:** indexed transcript text stays in the local seshctl SQLite — same locality as the prior `recall` implementation at `~/.recall/metadata.jsonl`, no network exposure. The CoreML model ships in the DMG and everything runs locally.

## New row layout — stacked by default

Session rows now stack sender / branch / preview vertically in one full-width column: bold sender at the top, branch demoted to a smaller monotone label, preview below in the larger title style. Local and remote rows both use the new layout. The legacy two-column layout is still available in **Settings → Appearance → Stacked row layout** if you prefer it.

With per-repo accent coloring on, the sender now picks up the repo's hashed accent so each row reads as one colored token per repo. Branch and worktree labels stay monotone — only the sender carries the accent. The unread accent bar and tree-view group dot are unchanged.

## Live row recaps

Local Claude Code rows now show the assistant's streaming response as the row preview within ~2s of the first text block landing, instead of staying pinned to `You: <last prompt>` for the duration of a multi-tool-call turn. If you queue a follow-up mid-response, the row flips back to the user prompt.

Pure-remote claude.ai Cowork rows get the same treatment: the row preview is now the latest assistant message (with the clock glyph) instead of the static session title.

## Smaller UX polish

- **Animated session-list reorders.** Rows spring to their new positions when the order changes (e.g. a session bumps to the top after a new message), and selection follows the row across the reorder. First refresh after the panel reopens still snaps without animation.
- **Yesterday timestamps are context-aware.** List view (time-sorted) shows yesterday rows as the clock time (e.g. `10:40 PM`) since the `Yesterday` section header already carries the day. Tree view (repo-grouped, no time headers) shows yesterday rows as `1d` instead of `Apr 14`.
- **Recall failures are now visible.** When semantic search fails (timeout, crash, unknown error), the search section shows an orange triangle row with the first line of the failure message. Previously the spinner just vanished and you got nothing.

## Fixes

- **`o` (open detail) now works on sessions that `cd`'d into a worktree mid-session.** Sessions that moved into `.claude/worktrees/<name>` after starting in the parent repo used to hit "No transcript available" because Claude re-derives the transcript path from the current cwd on every event. The same root cause was silently emptying those rows' previews. Resolved via a three-step path resolver: stored path → computed Claude path → conversation-id glob.
- **Row recap survives tool_use mid-turn.** Any assistant turn ending in a tool_use sub-event (e.g. `/juplan`'s interview prompts, `AskUserQuestion`) was clobbering the captured assistant text, so the row fell back to the last user prompt. Fixed by treating only `user` events as turn boundaries.
- **Transcript view no longer hangs on held navigation keys.** Held `Ctrl+B` (or `Ctrl+F`/`D`/`U`, `j`/`k`) on a large transcript used to saturate the main run loop at ~30 Hz key-repeat. Now snappy: cached scroll-view lookup, synchronous bounds updates with no per-keystroke animation. `gg` and `G` still animate.

## Under the hood

- `all-MiniLM-L6-v2` sentence embeddings, INT8-weight-quantized + FP32 compute, converted to CoreML and bundled at ~22MB.
- Tokenization via `huggingface/swift-transformers` (pinned to 1.3.3). Token IDs are byte-identical to the Python `tokenizers` library — there's a parity test asserting this against 20 reference strings.
- Storage and incremental indexing in seshctl's existing GRDB-backed SQLite via three new `recall_*` tables.
- DMG size goes from ~10MB to ~37MB — one-time cost on the full download; Sparkle deltas stay small because the model is byte-stable across releases.
